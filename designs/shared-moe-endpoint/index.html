Design notes

One endpoint, many agents

How a single large mixture-of-experts model, spread across three GPUs, can answer 20 people and subagents at the same time from one address, and keep taking new requests while it works.

The idea

Instead of running a separate model for every app, agent and person, load one big model once and put it behind one endpoint. A gateway in front gives every person their own key and tracks usage. Behind it, a model server batches every active request together on the GPUs.

A mixture-of-experts (MoE) model fits this well. It can be large in total (80 to 120 billion parameters) while only using a few billion of them for each word it writes, so it stays fast, and many users cost far less than many separate models.

The whole system

New requests join mid-flight

The model does not run a batch from start to finish. It works in tiny steps, one new word for every active conversation per step, a few hundredths of a second each. Before every step the scheduler can add new requests and drop finished ones. This is called continuous batching.

The scheduler's rules

  1. A new request arrives: its prompt is read in one quick pass, then it joins the active batch at the next step. Everyone already running gets slightly smaller slices of each step.
  2. A request finishes: it leaves at once and its memory goes straight to the next request.
  3. Memory is handed out in small blocks: short chats use a few, long ones use more, so no space is reserved for a worst case that never comes.
  4. Memory is full: new requests wait in line for a moment instead of crashing anything, and start as soon as someone finishes. The gateway can show "queued".
  5. Fairness: a cap per person, so twenty subagents from one job cannot crowd out a single chat.

One model or many specialists?

A second option is to keep one shared base model and swap in small task-specific add-ons (LoRA adapters), picked per request by a tiny router model. It trades some simplicity for specialists trained on real past tasks.

What 20 users should feel

  • One person alone: fast, roughly 40 to 70 words per second.
  • Twenty at once: each still gets roughly 15 to 30 words per second, faster than reading speed, and the first words arrive within a second or two.
  • The only cost of a busy server is that words arrive a little slower for everyone, never that someone is stuck behind the others.

These are estimates to be measured. The plan is a load test with 20 simulated users sending real agent-style tasks with tool calls, compared against the current models on speed, time to first word, failures and answer quality.
